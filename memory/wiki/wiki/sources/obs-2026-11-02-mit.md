# ⭐ Observation: 自研竖屏虚拟摄像头完成：MIT源码改造+表头插竖屏+两处换装坑

自研竖屏虚拟摄像头完成（2026-11-02）：基于 MIT 许可的 UnityCapture 源码改造（不复制 LuBot 专有 LuBotCam.dll），VS2022 Build Tools 编译出能力对齐 TK Cam 的驱动。核心改动：_media[] 分辨率表头部插入 {1080,1920}+{720,1280} —— 因 GetMediaType(0) 决定 m_mt 初始值、CheckMediaType 严格匹配、GetStreamCaps 跟表走，表头即默认协商格式；竖屏与 1920x1080 像素积相同故共享内存断言自动通过。编译要点：vcvars64.bat + cl /LD /O2 /MT(静态运行库) + streams.cpp(源码自带baseclasses) + UnityCaptureFilter.def + strmiids/uuid/ole32/oleaut32/winmm/advapi32/version/user32/gdi32/shell32。踩坑：注册表 InprocServer32 指向 dist\LiveStudio\driver\ 而非 driver\（换装错位置导致仍协商1920x1080，两处都要换）。验证：ffmpeg 协商 rawvideo bgr24 1080x1920；发送端720x1280填满零黑边（边缘亮度94-222，暗部为素材自身黑地面）；应用级E2E 186种颜色=真实素材。配套：发送端升原生1080x1920（LuBot同规格）、driver/NOTICE.txt(MIT署名)、原版横屏DLL改名存vcam_build。许可确认：UnityCaptureFilter=MIT，可商用分发需保留版权声明。
